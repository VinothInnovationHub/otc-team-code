Network reality — three deployments, one constant

All three were tried on the current VNet/subnet. Each hit Azure's network layer at a different point — not application code.

What was tried

1 · Adaptive Card + paperclip → App Service
Inbound Allowed — reaches App Service through its private endpoint.
Outbound Blocked — App Service's dedicated VNet/subnet egress doesn't permit the call out to SharePoint/OneDrive to fetch the attached file.
2 · Teams WebView / Tab → App Service
Inbound Blocked — the private DNS zone for the tab's URL only resolves over GVPN; standard laptops never get a DNS answer, so the request never leaves the browser.
3 · Hosted Agent via REST API (Foundry)
Upload Works — the agent's public Activity Protocol endpoint accepts the inbound message.
Download Blocked — same outbound VNet egress rule as Scenario 1 stops the file from coming back.

All three fail at the same layer: Azure's network controls (NSG, firewall, private DNS) on this VNet/subnet — not the application code, and not the choice of App Service vs. a hosted agent vs. any other compute. Every Azure compute resource placed in this environment is controlled the same way, inbound and outbound, until its specific IP ranges/domains are explicitly allow-listed by network/security. No deployment option avoids this.

The only path that doesn't depend on a network change: upload and download move directly between the browser and Blob Storage's own public endpoint, authorized by a single-file SAS link expiring in 5–10 minutes.

That path still requires explicit Security approval — it's a public-internet-reachable endpoint, even though access is scoped to one file and time-limited.

Recommended — three concrete actions

  1. Allow SharePoint 443 (outbound rule). Add one outbound NSG/firewall allow rule on the App Service's egress subnet — destination *.sharepoint.com / graph.microsoft.com, port 443 (the SharePointOnline service tag covers both). Fixes Scenario 1's blocked attachment fetch and Scenario 3's blocked download; completes the current Adaptive Card + paperclip design end-to-end, since inbound already works today. Owner: Network/Firewall team · Effort: one rule change
  2. Blob Storage direct upload/download. Bot issues a single-file SAS token, 5–10 min expiry; browser uploads/downloads straight against Blob Storage's public endpoint. Removes the SharePoint/OneDrive dependency entirely — works regardless of any NSG/firewall state, no network ticket required. Owner: App team (code only) · Needs: Security sign-off
  3. Resolve DNS for the WebView/Tab path. Publish a public DNS record for the tab's hostname pointing at App Gateway's existing public frontend IP, instead of relying only on the private DNS zone tied to GVPN — paired with the same inbound NSG/WAF fix, since resolving the name alone doesn't yet pass the gate behind it. Fixes Scenario 2 end-to-end, but only needed if a WebView/Tab UI is kept — the Adaptive Card path already avoids this requirement completely. Owner: Network/DNS team · Effort: DNS record + 1 rule change
